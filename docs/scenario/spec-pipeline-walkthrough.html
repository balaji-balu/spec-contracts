Spec Pipeline Walkthrough

One spec, followed from the words a user types into the UI to a tagged spec the execution loop can build. It shows every agent step, every verify and eval gate, and every human decision. The artifacts it produces are the ones in examples/.

  • 66steps in 4 phases
  • 6verify runs
  • 2verify failures
  • 4eval runs
  • 1eval failure
  • 7human inputs (answers + approvals)

The platform

Your redrawn sketch, with the wiring the scenario relies on. The engine owns control flow, pi agents own judgment inside a step, and git holds the state.

Scroll sideways on narrow screens.

  • Every agent runs on pi. The sketch still labels Requirement analysis and DDD as hermes.
  • The UI talks to the engine, not to the Intent agent. The intent chat is a pi RPC session the reconciler hosts. The UI only relays it.
  • BA and architect act through the UI. Every button is a PR approval or a comment command such as /answer RAF-1.
  • Verify and eval are separate gates. The deterministic lint runs first and triggers repair. The judge runs second and triggers revise.
  • Git is on the drawing. It is the workflow state. The engine keeps none of its own.
  • AGENTS.md joins skills, templates and prompts as pinned per-step config. The constitution stays in the org KB, pinned by version.

Verify & handoff

22 Sep →

A whole-spec verify on main, a ready tag, and the feedback path from execution back to eval.

  1. Reconciler → Verify

    Whole-spec verify on main

  2. Verify → Reconcilerpassed

    C1–C9 ✓ · no stale pins · metrics.json

  3. Reconciler → Git / PR

    Tag SPEC-0001/v1.1-ready
